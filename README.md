# Git GitFlow Plugin v2.0

Плагин для автоматизации работы с GitFlow в git bash. Упрощает процесс доведения изменений, создания hotfix-ов и управления ветками в соответствии с корпоративным GitFlow.

## 🚀 Возможности

- **Интерактивное меню** для выбора действий
- **Выбор коммитов** для доведения (количество или конкретные коммиты)
- **Автоматическое разрешение конфликтов** с возможностью продолжения
- **Обновление PR** без засорения истории
- **Создание hotfix веток** для всех типов версий
- **Статус и мониторинг** текущего состояния
- **Сохранение состояния** при конфликтах

## 📋 Структура GitFlow

### Основные ветки
- `master` - ветка стабилизации
- `test` - ветка разработки  
- `release_oe` - ветка опытной эксплуатации
- `release_pe` - ветка промышленной эксплуатации

### Рабочие ветки
- `tasks/PARENT_JIRA/JIRA` - feature ветка
- `tasks/PARENT_JIRA/stable_JIRA` - ветка стабилизации фичи (от master)
- `tasks/PARENT_JIRA/test_JIRA` - merge ветка для test
- `tasks/PARENT_JIRA/release_oe_JIRA` - merge ветка для release_oe
- `tasks/PARENT_JIRA/release_pe_JIRA` - merge ветка для release_pe

### Hotfix ветки
- `hotfixes/pe/JIRA` - hotfix для PE версии
- `hotfixes/oe/JIRA` - hotfix для OE версии  
- `hotfixes/iz/JIRA` - hotfix для IZ версии

### Версионные ветки
- `versions/pe/00.00.00.0` - версия для PE
- `versions/oe/00.00.00.0` - версия для OE
- `versions/iz/00.00.00.0` - версия для IZ

## 🛠 Установка

### Автоматическая установка
```bash
./install.sh
```

### Ручная установка
1. Скопируйте `git-gitflow` в директорию из `$PATH`:
```bash
sudo cp git-gitflow /usr/local/bin/
sudo chmod +x /usr/local/bin/git-gitflow
```

2. Или добавьте текущую директорию в `$PATH`:
```bash
export PATH=$PATH:$(pwd)
```

## 📖 Использование

### Интерактивное меню
```bash
git gitflow
```
Запускает интерактивное меню с доступными действиями в зависимости от текущей ветки.

### Команды

#### Доведение изменений
```bash
# Доведение в test (по умолчанию)
git gitflow deliver

# Доведение в release_oe
git gitflow deliver release_oe

# Доведение в release_pe  
git gitflow deliver release_pe
```

**Процесс доведения:**
1. Выбор коммитов для доведения
2. Создание/обновление stable ветки от master
3. Cherry-pick выбранных коммитов
4. Опциональный сквош коммитов
5. Создание/обновление merge ветки
6. Слияние stable ветки в merge ветку
7. Отправка на сервер

#### Обновление PR
```bash
# Обновление PR в test
git gitflow update

# Обновление PR в release_oe
git gitflow update release_oe

# Обновление PR в release_pe
git gitflow update release_pe
```

**Процесс обновления:**
1. Удаление локальной merge ветки
2. Сброс stable ветки к master
3. Повторный cherry-pick коммитов
4. Принудительное обновление веток на сервере

#### Создание hotfix
```bash
# Создание hotfix ветки
git gitflow hotfix pe TASK-123

# Создание hotfix с cherry-pick коммита
git gitflow hotfix oe TASK-456 abc123def

# Создание hotfix для iz
git gitflow hotfix iz TASK-789
```

#### Продолжение после конфликтов
```bash
# После разрешения конфликтов
git add .
git cherry-pick --continue  # или git commit для merge конфликтов
git gitflow continue
```

#### Статус и справка
```bash
# Показать статус текущей ветки
git gitflow status

# Показать справку
git gitflow help
```

## 🎯 Выбор коммитов

При доведении изменений плагин предлагает несколько вариантов выбора коммитов:

1. **По номерам**: `1 3 5` - выбрать коммиты 1, 3 и 5 из списка
2. **По количеству**: `3` - выбрать последние 3 коммита
3. **Все коммиты**: `Enter` - выбрать все доступные коммиты

Merge коммиты автоматически исключаются из списка.

## 🔧 Разрешение конфликтов

### Cherry-pick конфликты
1. Плагин останавливается при конфликте
2. Разрешите конфликты вручную
3. Выполните:
```bash
git add .
git cherry-pick --continue
git gitflow continue
```

### Merge конфликты  
1. Плагин останавливается при конфликте слияния
2. Разрешите конфликты вручную
3. Выполните:
```bash
git add .
git commit
git gitflow continue
```

## 📊 Статус операций

Плагин сохраняет состояние при конфликтах в файле `.gitflow_state`. Это позволяет:
- Продолжить операцию после разрешения конфликтов
- Отследить текущий прогресс
- Восстановить контекст при перезапуске

## 🎨 Интерфейс

### Цветовая схема
- 🔴 **Красный** - ошибки
- 🟢 **Зеленый** - успешные операции  
- 🟡 **Желтый** - предупреждения
- 🔵 **Синий** - информация
- 🟦 **Голубой** - заголовки разделов
- 🟣 **Фиолетовый** - специальные сообщения

### Интерактивное меню
Меню адаптируется к текущему контексту:
- **Feature ветка** - полный набор операций доведения
- **Hotfix ветка** - ограниченный набор действий
- **Другие ветки** - базовые операции
- **Незавершенная операция** - возможность продолжения

## 🔍 Примеры использования

### Стандартное доведение
```bash
# Находясь в ветке tasks/PROJ-100/TASK-123
git gitflow deliver

# Выбираем последние 2 коммита
> 2

# Плагин автоматически:
# 1. Создает tasks/PROJ-100/stable_TASK-123 от master
# 2. Переносит 2 последних коммита
# 3. Создает tasks/PROJ-100/test_TASK-123 от test  
# 4. Мержит stable ветку
# 5. Отправляет на сервер
```

### Обновление PR
```bash
# После доработки в feature ветке
git gitflow update

# Плагин:
# 1. Удаляет старую merge ветку
# 2. Пересоздает stable ветку
# 3. Принудительно обновляет PR
```

### Создание hotfix
```bash
# Создание hotfix для PE версии
git gitflow hotfix pe URGENT-001 abc123

# Плагин:
# 1. Находит versions/pe/* ветку
# 2. Создает hotfixes/pe/URGENT-001
# 3. Переносит коммит abc123
# 4. Отправляет на сервер
```

## ⚠️ Важные замечания

1. **Проверка изменений**: Плагин предупреждает о незафиксированных изменениях
2. **Соглашения именования**: Строго следует корпоративным соглашениям
3. **Автоматическое обновление**: Подтягивает изменения с сервера перед операциями
4. **Безопасность**: Сохраняет состояние при ошибках для восстановления

## 🐛 Устранение неполадок

### Плагин не запускается
```bash
# Проверьте права доступа
chmod +x git-gitflow

# Проверьте PATH
echo $PATH
```

### Ошибки именования веток
```bash
# Убедитесь что находитесь в правильной ветке
git branch

# Проверьте формат: tasks/PARENT_JIRA/JIRA
```

### Конфликты при cherry-pick
```bash
# Посмотрите статус
git status

# Разрешите конфликты в файлах
# Затем продолжите
git add .
git cherry-pick --continue
git gitflow continue
```
