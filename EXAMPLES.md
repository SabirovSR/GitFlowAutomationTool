# Примеры использования Git GitFlow Plugin

## 🎯 Сценарии использования

### 1. Стандартное доведение фичи

**Ситуация**: Вы завершили работу над задачей в ветке `tasks/PROJ-100/TASK-123` и хотите довести изменения до `test`.

```bash
# Находимся в feature ветке
$ git branch
* tasks/PROJ-100/TASK-123
  master

# Запускаем доведение
$ git gitflow deliver

=== ВЫБОР КОММИТОВ ===
Доступные коммиты для доведения:
1) abc123def - Добавлен новый функционал
2) def456ghi - Исправлены тесты  
3) ghi789jkl - Обновлена документация

Опции выбора:
1) Ввести номера коммитов через пробел (например: 1 3 5)
2) Ввести количество последних коммитов (например: 3)  
3) Нажать Enter для всех коммитов

Ваш выбор: 3

✔ Выбрано коммитов: 3

=== РАБОТА СО STABLE ВЕТКОЙ ===
ℹ Создание новой ветки: tasks/PROJ-100/stable_TASK-123 от master

=== ПЕРЕНОС КОММИТОВ ===
ℹ Cherry-pick коммита 1/3: abc123def
✔ Коммит успешно перенесен
ℹ Cherry-pick коммита 2/3: def456ghi  
✔ Коммит успешно перенесен
ℹ Cherry-pick коммита 3/3: ghi789jkl
✔ Коммит успешно перенесен

=== СКВОШ КОММИТОВ ===
⚠ Рекомендуется сквошить коммиты в один
Выполнить интерактивный rebase для сквоша? (y/n) y

✔ Stable ветка отправлена на сервер

=== СОЗДАНИЕ MERGE ВЕТКИ ===
ℹ Создание новой ветки: tasks/PROJ-100/test_TASK-123 от test

=== СЛИЯНИЕ ИЗМЕНЕНИЙ ===
✔ Успешное слияние
✔ Merge ветка отправлена на сервер

✔ ДОВЕДЕНИЕ ЗАВЕРШЕНО
----------------------------------------
Ветка для PR: tasks/PROJ-100/test_TASK-123
Целевая ветка: test
----------------------------------------
```

### 2. Доведение с выбором конкретных коммитов

**Ситуация**: Из 5 коммитов нужно довести только 1-й и 3-й.

```bash
$ git gitflow deliver

=== ВЫБОР КОММИТОВ ===
Доступные коммиты для доведения:
1) abc123def - Основной функционал
2) def456ghi - Временное решение (не нужно)
3) ghi789jkl - Исправление бага
4) jkl012mno - Отладочный код (не нужно)  
5) mno345pqr - Обновление зависимостей

Ваш выбор: 1 3 5

✔ Выбрано коммитов: 3
• abc123def - Основной функционал
• ghi789jkl - Исправление бага  
• mno345pqr - Обновление зависимостей

# Далее процесс идет как обычно...
```

### 3. Разрешение конфликтов при cherry-pick

**Ситуация**: При переносе коммита возник конфликт.

```bash
$ git gitflow deliver

# ... выбор коммитов ...

=== ПЕРЕНОС КОММИТОВ ===
ℹ Cherry-pick коммита 1/2: abc123def
✗ ОШИБКА: Конфликт при cherry-pick коммита: abc123def

⚠ Для продолжения после разрешения конфликтов выполните:
git add .
git cherry-pick --continue  
git gitflow continue

# Разрешаем конфликты вручную
$ vim src/main.js  # исправляем конфликты
$ git add .
$ git cherry-pick --continue
$ git gitflow continue

=== ПРОДОЛЖЕНИЕ ОПЕРАЦИИ ===
ℹ Операция: CHERRY_PICK
ℹ Продолжение cherry-pick операции
✔ Stable ветка отправлена на сервер

# ... продолжение процесса ...
```

### 4. Обновление существующего PR

**Ситуация**: После создания PR нужно внести небольшие правки.

```bash
# Вносим изменения в feature ветку
$ git add .
$ git commit -m "Мелкие исправления по ревью"

# Обновляем PR
$ git gitflow update

=== ОБНОВЛЕНИЕ PR ===
ℹ Удаление локальной ветки: tasks/PROJ-100/test_TASK-123
ℹ Обновление stable ветки

=== ВЫБОР КОММИТОВ ===
# ... выбираем все коммиты включая новый ...

✔ PR успешно обновлен
----------------------------------------
Обновленная ветка для PR: tasks/PROJ-100/test_TASK-123
----------------------------------------
```

### 5. Создание hotfix для критического бага

**Ситуация**: Нужно срочно исправить баг в production версии PE.

```bash
# Сначала находим коммит с исправлением в test ветке
$ git log --oneline test | grep "Fix critical bug"
xyz789abc Fix critical bug in payment module

# Создаем hotfix
$ git gitflow hotfix pe URGENT-001 xyz789abc

=== СОЗДАНИЕ HOTFIX ВЕТКИ ===
ℹ Найдена версионная ветка: versions/pe/01.02.03.0
ℹ Создание новой ветки: hotfixes/pe/URGENT-001 от versions/pe/01.02.03.0

=== ПЕРЕНОС КОММИТА ===  
ℹ Cherry-pick коммита: xyz789abc
✔ Коммит успешно перенесен
✔ Hotfix ветка отправлена на сервер

----------------------------------------
Hotfix ветка: hotfixes/pe/URGENT-001
Версионная ветка: versions/pe/01.02.03.0
----------------------------------------
```

### 6. Доведение в release_oe минуя test

**Ситуация**: Изменения нужно довести напрямую в release_oe.

```bash
$ git gitflow deliver release_oe

# Процесс аналогичен обычному доведению, но:
# - stable ветка мержится в tasks/PROJ-100/release_oe_TASK-123
# - базовой веткой является release_oe вместо test

✔ ДОВЕДЕНИЕ ЗАВЕРШЕНО
----------------------------------------
Ветка для PR: tasks/PROJ-100/release_oe_TASK-123
Целевая ветка: release_oe  
----------------------------------------
```

### 7. Использование интерактивного меню

**Ситуация**: Не помните команды, используете меню.

```bash
$ git gitflow

=== GITFLOW МЕНЮ ===
Текущая ветка: tasks/PROJ-100/TASK-123

Доступные действия:

1) Доведение в test
2) Доведение в release_oe
3) Доведение в release_pe
4) Обновление PR в test
5) Обновление PR в release_oe  
6) Обновление PR в release_pe
7) Создать hotfix
8) Показать статус
9) Справка
0) Выход

Выберите действие: 1

# Запускается git gitflow deliver
```

### 8. Проверка статуса веток

**Ситуация**: Нужно понять текущее состояние веток.

```bash
$ git gitflow status

=== СТАТУС GITFLOW ===
Текущая ветка: tasks/PROJ-100/TASK-123
Parent JIRA: PROJ-100
JIRA: TASK-123

Связанные ветки:
  Stable: tasks/PROJ-100/stable_TASK-123
  Test: tasks/PROJ-100/test_TASK-123  
  Release OE: tasks/PROJ-100/release_oe_TASK-123
  Release PE: tasks/PROJ-100/release_pe_TASK-123

Статус веток:
  ✓ tasks/PROJ-100/stable_TASK-123 (локально)
  ↓ tasks/PROJ-100/test_TASK-123 (только удаленно)
  ✗ tasks/PROJ-100/release_oe_TASK-123 (не существует)
  ✗ tasks/PROJ-100/release_pe_TASK-123 (не существует)
```

### 9. Восстановление после прерывания

**Ситуация**: Процесс прервался из-за конфликта, нужно продолжить.

```bash
# При запуске плагин обнаруживает незавершенную операцию
$ git gitflow

=== GITFLOW МЕНЮ ===
⚠ Найдено незавершенное состояние операции

1) Продолжить операцию
2) Показать статус  
3) Справка
4) Выход

Выберите действие: 1

=== ПРОДОЛЖЕНИЕ ОПЕРАЦИИ ===
ℹ Операция: MERGE
ℹ Продолжение merge операции
✔ Операция успешно завершена
```

### 10. Создание hotfix без готового коммита

**Ситуация**: Нужно создать hotfix ветку для разработки исправления.

```bash
$ git gitflow hotfix iz TASK-999

=== СОЗДАНИЕ HOTFIX ВЕТКИ ===
ℹ Найдена версионная ветка: versions/iz/02.01.00.5
✔ Hotfix ветка создана

----------------------------------------
Hotfix ветка: hotfixes/iz/TASK-999
Версионная ветка: versions/iz/02.01.00.5  
----------------------------------------
ℹ Добавьте изменения и выполните cherry-pick вручную

# Теперь можно работать в hotfix ветке
$ git branch
* hotfixes/iz/TASK-999
  master
  tasks/PROJ-100/TASK-123
```

## 🔧 Полезные советы

### Алиасы для быстрого доступа
```bash
# Добавьте в ~/.bashrc или ~/.zshrc
alias gf='git gitflow'
alias gfd='git gitflow deliver'
alias gfu='git gitflow update'  
alias gfs='git gitflow status'

# Использование
$ gf          # Открыть меню
$ gfd         # Доведение в test
$ gfu         # Обновление PR
$ gfs         # Показать статус
```

### Проверка перед доведением
```bash
# Всегда проверяйте что в feature ветке
$ git branch --show-current
tasks/PROJ-100/TASK-123

# Проверьте коммиты
$ git log --oneline master..HEAD
abc123def Основные изменения
def456ghi Тесты  
ghi789jkl Документация

# Убедитесь что нет незафиксированных изменений
$ git status
On branch tasks/PROJ-100/TASK-123
nothing to commit, working tree clean
```

### Работа с конфликтами
```bash
# При конфликте посмотрите какие файлы затронуты
$ git status
Unmerged paths:
  both modified:   src/main.js

# Откройте файл и найдите конфликты
$ vim src/main.js
# Найдите блоки <<<<<<< ======= >>>>>>>

# После разрешения добавьте файлы
$ git add src/main.js

# Продолжите операцию
$ git cherry-pick --continue  # для cherry-pick
$ git commit                  # для merge
$ git gitflow continue
```

### Отмена операций
```bash
# Если нужно отменить cherry-pick
$ git cherry-pick --abort

# Если нужно отменить merge
$ git merge --abort

# Удалить файл состояния
$ rm .gitflow_state

# Вернуться в исходную ветку
$ git checkout tasks/PROJ-100/TASK-123
```
