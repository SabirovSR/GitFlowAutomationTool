# Часто задаваемые вопросы (FAQ)

## 🤔 Общие вопросы

### Q: Чем этот плагин отличается от оригинального git-deliver?

**A:** Новый плагин имеет множество улучшений:
- **Интерактивное меню** для выбора действий
- **Выбор коммитов** - можно выбрать конкретные коммиты или количество
- **Обработка конфликтов** - возможность продолжить после разрешения
- **Обновление PR** - без засорения истории
- **Поддержка hotfix** - создание hotfix веток для всех типов версий
- **Сохранение состояния** - восстановление после прерывания
- **Улучшенный интерфейс** - цветной вывод и понятные сообщения

### Q: Можно ли использовать плагин с существующими ветками?

**A:** Да, плагин работает с любыми существующими ветками, которые соответствуют naming convention:
- `tasks/PARENT_JIRA/JIRA` - для feature веток
- `hotfixes/TYPE/JIRA` - для hotfix веток

### Q: Что делать если я не в правильной ветке?

**A:** Плагин проверит название ветки и покажет ошибку если оно не соответствует конвенции. Переключитесь на правильную ветку:
```bash
git checkout tasks/PROJ-100/TASK-123
```

## 🔧 Установка и настройка

### Q: Плагин не запускается, что делать?

**A:** Проверьте несколько вещей:

1. **Права доступа:**
```bash
chmod +x git-gitflow
```

2. **PATH переменная:**
```bash
echo $PATH
which git-gitflow
```

3. **Расположение файла:**
```bash
# Должен быть в одной из директорий PATH
ls -la /usr/local/bin/git-gitflow
```

### Q: Можно ли установить плагин только для текущего пользователя?

**A:** Да, используйте домашнюю директорию:
```bash
mkdir -p ~/.local/bin
cp git-gitflow ~/.local/bin/
chmod +x ~/.local/bin/git-gitflow

# Добавьте в ~/.bashrc
export PATH=$PATH:~/.local/bin
```

### Q: Как обновить плагин до новой версии?

**A:** Просто замените файл:
```bash
# Скачайте новую версию
wget https://example.com/git-gitflow

# Замените старый файл
sudo cp git-gitflow /usr/local/bin/
sudo chmod +x /usr/local/bin/git-gitflow
```

## 🚀 Использование

### Q: Как выбрать только некоторые коммиты для доведения?

**A:** При запуске `git gitflow deliver` выберите опцию ввода номеров:
```
Доступные коммиты для доведения:
1) abc123def - Основной функционал
2) def456ghi - Временное решение  
3) ghi789jkl - Исправление бага

Ваш выбор: 1 3
```

### Q: Можно ли довести только последний коммит?

**A:** Да, введите `1` при выборе количества коммитов:
```
Ваш выбор: 1
```

### Q: Что делать если нужно исключить merge коммиты?

**A:** Плагин автоматически исключает merge коммиты из списка для доведения.

### Q: Как довести изменения сразу в release_pe минуя test?

**A:** Используйте параметр target:
```bash
git gitflow deliver release_pe
```

## ⚠️ Конфликты и ошибки

### Q: Возник конфликт при cherry-pick, что делать?

**A:** Следуйте инструкциям плагина:

1. **Разрешите конфликты в файлах:**
```bash
vim src/conflicted_file.js  # исправьте конфликты
```

2. **Добавьте исправленные файлы:**
```bash
git add .
```

3. **Продолжите cherry-pick:**
```bash
git cherry-pick --continue
```

4. **Продолжите операцию плагина:**
```bash
git gitflow continue
```

### Q: Конфликт при merge, как быть?

**A:** Аналогично cherry-pick, но вместо `--continue` используйте `commit`:

1. Разрешите конфликты
2. `git add .`
3. `git commit`
4. `git gitflow continue`

### Q: Плагин завис на конфликте, как сбросить?

**A:** Отмените текущую операцию и очистите состояние:
```bash
# Отмена cherry-pick или merge
git cherry-pick --abort
# или
git merge --abort

# Очистка состояния плагина
rm .gitflow_state

# Возврат в исходную ветку
git checkout tasks/PROJ-100/TASK-123
```

### Q: Ошибка "Не найдена версионная ветка" при создании hotfix

**A:** Убедитесь что версионные ветки существуют на сервере:
```bash
# Обновите информацию о ветках
git fetch origin

# Проверьте наличие версионных веток
git branch -r | grep versions/pe/
git branch -r | grep versions/oe/
git branch -r | grep versions/iz/
```

## 🔄 Обновление PR

### Q: В чем разница между deliver и update?

**A:** 
- **deliver** - создает новые ветки для первого PR
- **update** - обновляет существующий PR, перезаписывая историю

### Q: Безопасно ли использовать update?

**A:** Да, но учтите:
- Локальные merge ветки будут удалены и пересозданы
- История в удаленных merge ветках будет перезаписана (force push)
- Это нормально для PR веток, но не делайте это с основными ветками

### Q: Можно ли обновить PR если он уже имеет аппрувы?

**A:** Технически да, но:
- Аппрувы могут сброситься (зависит от настроек репозитория)
- Лучше согласовать с командой перед обновлением

## 🏥 Hotfix

### Q: Как создать hotfix если не знаю какой коммит нужен?

**A:** Создайте ветку без коммита:
```bash
git gitflow hotfix pe URGENT-001
# Затем вручную найдите и перенесите нужный коммит
```

### Q: Можно ли создать hotfix от произвольной ветки?

**A:** Нет, hotfix создается только от версионных веток `versions/TYPE/VERSION`. Это гарантирует что исправление применяется к конкретной версии.

### Q: Что если версионная ветка не найдена?

**A:** Проверьте:
1. Существует ли ветка на сервере: `git branch -r | grep versions/pe/`
2. Правильно ли указан тип: `pe`, `oe` или `iz`
3. Обновите информацию о ветках: `git fetch origin`

## 📊 Статус и мониторинг

### Q: Как посмотреть какие ветки уже созданы?

**A:** Используйте команду статуса:
```bash
git gitflow status
```

### Q: Что означают символы в статусе веток?

**A:**
- `✓` - ветка существует локально
- `↓` - ветка существует только на сервере
- `✗` - ветка не существует

### Q: Как узнать есть ли незавершенные операции?

**A:** Плагин автоматически покажет предупреждение при запуске, или проверьте файл:
```bash
cat .gitflow_state
```

## 🎨 Кастомизация

### Q: Можно ли изменить цвета вывода?

**A:** Да, отредактируйте переменные в начале скрипта:
```bash
RED='\033[0;31m'
GREEN='\033[0;32m'
# и т.д.
```

### Q: Как отключить цветной вывод?

**A:** Установите все цветовые переменные в пустые строки:
```bash
RED=''
GREEN=''
NC=''
```

### Q: Можно ли изменить naming convention?

**A:** Да, но потребуется изменить регулярные выражения в функции `parse_current_branch()`.

## 🔒 Безопасность

### Q: Безопасно ли использовать force push?

**A:** Плагин использует force push только для PR веток (merge ветки), что безопасно. Основные ветки (master, test, release_*) никогда не перезаписываются.

### Q: Что если случайно запустить плагин в master?

**A:** Плагин проверит название ветки и не позволит выполнить операции в неправильных ветках.

### Q: Сохраняются ли данные при ошибках?

**A:** Да, плагин сохраняет состояние в `.gitflow_state` и позволяет продолжить операцию после исправления проблем.

## 🚨 Экстренные ситуации

### Q: Плагин сломал мой репозиторий, что делать?

**A:** Не паникуйте! Плагин не изменяет основные ветки. Проверьте:

1. **Ваша исходная ветка цела:**
```bash
git checkout tasks/PROJ-100/TASK-123
git log --oneline  # должны быть все ваши коммиты
```

2. **Восстановите из удаленного репозитория:**
```bash
git fetch origin
git reset --hard origin/tasks/PROJ-100/TASK-123
```

3. **Удалите проблемные ветки:**
```bash
git branch -D tasks/PROJ-100/stable_TASK-123
git branch -D tasks/PROJ-100/test_TASK-123
```

### Q: Как полностью откатить операцию плагина?

**A:** Удалите созданные ветки:
```bash
# Локально
git branch -D tasks/PROJ-100/stable_TASK-123
git branch -D tasks/PROJ-100/test_TASK-123

# На сервере (осторожно!)
git push origin --delete tasks/PROJ-100/stable_TASK-123
git push origin --delete tasks/PROJ-100/test_TASK-123

# Очистите состояние
rm .gitflow_state
```

### Q: Потерялись коммиты, как восстановить?

**A:** Git редко теряет коммиты полностью:
```bash
# Найдите потерянные коммиты
git reflog

# Восстановите по хешу
git checkout abc123def
git checkout -b recovery-branch

# Или восстановите ветку
git branch recovery-branch abc123def
```
