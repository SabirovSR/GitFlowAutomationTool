# 📦 GitFlow Automation Tool - Обзор проекта

## 🎯 Цель проекта

Автоматизация корпоративного GitFlow процесса с поддержкой:
- Delivery изменений в test/release_oe/release_pe
- Работы с hotfix для версионных веток
- Продолжения операций после конфликтов
- Интерактивного меню для удобства использования

---

## 📁 Структура проекта

```
.
├── git-flow                # Главное интерактивное меню (9KB)
├── git-flow-common         # Библиотека общих функций (9KB)
├── git-flow-deliver        # Автоматизация delivery (8KB)
├── git-flow-hotfix         # Работа с hotfix (6KB)
├── git-flow-continue       # Продолжение после конфликтов (11KB)
├── install.sh              # Скрипт установки (2KB)
├── README.md               # Полная документация
├── QUICKSTART.md           # Быстрый старт
├── EXAMPLES.md             # Подробные примеры
├── ARCHITECTURE.md         # Архитектура системы
├── PROJECT_OVERVIEW.md     # Обзор проекта (этот файл)
├── VERSION                 # Информация о версии
└── .gitignore              # Git ignore файл
```

**Общий размер:** ~45KB кода + документация  
**Язык:** Bash  
**Версия:** 2.0

## 🔄 Поток работы

### Стандартный Delivery

```
Developer → Feature Branch
     ↓
git flow deliver
     ↓
Select Commits → Select Environment → Process
     ↓                    ↓                ↓
  Cherry-pick      test/release_oe    Squash
     ↓              release_pe           ↓
Stable Branch    ←-------------------  Push
     ↓
   Merge
     ↓
 Merge Branch → Push → Pull Request
     ↓
   Success! 🎉
```

### Delivery с конфликтом

```
git flow deliver
     ↓
Cherry-pick → Conflict! 💥
     ↓
Save State → Show Instructions
     ↓
[Developer resolves conflict]
     ↓
git add → git flow continue
     ↓
Load State → Resume → Complete! ✅
```

## 🎨 Дизайн-решения

### 1. Модульная архитектура
- Общие функции вынесены в git-flow-common
- Каждая команда в отдельном файле
- Легко расширяется новыми командами

### 2. Управление состоянием
- Файл .git/git-flow-state для персистентности
- Автоматическое восстановление
- Защита от потери данных

### 3. Безопасность
- force-with-lease вместо force
- Проверки на каждом шаге
- Подтверждения для критичных операций

### 4. UX
- Цветной вывод для читаемости
- Информативные сообщения
- Интерактивные промпты
- Прогресс операций

## 🔧 Технические детали

### Используемые техники

1. **Bash функции и модули**
   - export -f для экспорта функций
   - source для подключения модулей

2. **Управление состоянием**
   - Сохранение в файл
   - Чтение и восстановление

3. **Git операции**
   - cherry-pick с обработкой конфликтов
   - merge с --no-ff
   - force-with-lease для безопасности
   - rev-list для фильтрации коммитов

4. **Интерактивный ввод**
   - read с опциями
   - Валидация ввода
   - Значения по умолчанию

## 🐛 Известные ограничения

1. Работает только с конкретной структурой веток
2. Требует Bash >= 4.0
3. Не поддерживает Windows (только Linux/Mac)
4. Не создает PR автоматически (только ветки)

## 📞 Поддержка и FAQ

### Частые вопросы

**Q: Что делать если команда не найдена?**  
A: Проверьте PATH и права доступа, см. README.md → Решение проблем

**Q: Можно ли отменить операцию?**  
A: До push - да (git cherry-pick --abort / git merge --abort)

**Q: Как обновить плагин?**  
A: git pull и повторный ./install.sh

**Q: Работает ли на Windows?**  
A: Да, через Git Bash

**Q: Можно ли кастомизировать названия веток?**  
A: В v2.0 - нет, запланировано в v3.0
